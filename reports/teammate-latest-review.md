## bugs, metric risks and unvalidated assumptions

- **in-candidate truth inflation:** `new/scripts/blend_cv.py:27-38`, `eval_holdout.py:10-26` and `compose.py:113-125` set each reference's truth degree `a` from rows that survived candidate generation. a true link missing from candidates disappears from the denominator; a positive owner with zero candidates can even receive the implicit score of a correct singleton. tiny counterexample: one true prediction and one missed true link score **1.0** with `a=1` in this code, versus **1.25/(0.25×2+1)=0.8333** with full truth. hard-coded `N_HOLD=22144` in two scripts adds an unverified population assumption. [official macro metric](../Ml_Challenge.txt#L112-L125).
- **competitor projection:** `new/src/amzn/blend.py:138-151` and `new/scripts/blend_cv.py:56-85` load only bucket <100 source1 rows; `one_to_one` then sees just their rival pairs. `new/scripts/compose.py:79-109` also builds its confident-owner and competing-claim features from that reduced frame. if target `t` has scores 0.70 for evaluated owner a and 0.95 for owner b outside those buckets, the cv projection credits a with a winning score although b wins in full inference. neither random row order nor owner-bucket cv repairs this; joining full-population statistics **after** projection is too late. [current full-incidence evaluation](../src/opt.py#L64-L82).
- **composition self-inclusion and split contamination:** `new/scripts/compose.py:81-96` counts all `p>=0.9` pairs as already confident, including the very 0.9–0.99 pair being evaluated; for a sole 0.95 source2 candidate it sets `c2=1` and evaluates the prior for *two* source2 links after “adding” it. `joint_tables()` reads **all** training labels, including cv validation owners (`:62-72,127-141`); competitor claims of one target can also straddle folds (`:97-109,133-142`). that cv does not prove owner/target-isolated deployment gains. rebuild label priors on fit owners only, exclude each scored pair from its own confident counts, and compare the same full-competitor candidates.
- **accent and permissive acronym edge cases, reproduced without dataset access:** an import-only string probe of `new/src/amzn/france_rule.py:37-45,55-85` returns `kind('ÉPL') == 'other'`, even though folded source initials include `epl`; `consistent('acronym','A','Acme Baker','acme baker') == True`. accent folding therefore does not classify an accented target acronym, while one-letter initials can accept many businesses. `new/src/amzn/france_rule.py:182-187` resolves rival references by `sort(...).unique('ti',keep='first')` rather than requiring an unambiguous owner. avoid importing that selection rule wholesale.
- **france claims are hypotheses, not ground truth:** `new/docs/experiments.md:362-389,412-434` describes leaderboard values and says 2.4k/24.5k france additions or exclusions are “true”; no france test labels are available (`../Ml_Challenge.txt:36-38`). source and public-score claims cannot prove per-france correctness or the alleged causal contribution of a single rule. the “france emptied” back-solve assumes us/india performance and public split composition. `new/scripts/merge_france.py:37-47` treats generator flags as truth proxies, not labels.
- **candidate/validation boundary:** `new/src/amzn/hybrid.py:29-38,122-125` writes all blend-loaded stage-1 pairs, not necessarily the last set presented to the filtered decoder; `new/scripts/final_assemble.sh:21-26` can splice decisions from another candidate universe and reuse the prior file. a passing supplied validator does not prove the candidate file is the actual pre-matcher set or that no matches fall outside it: the subset check is warning-only. [challenge contract](../Ml_Challenge.txt#L63-L79).
